## 3. Arquitetura de Software

### 3.1 Padrões Arquiteturais

#### Arquitetura Multicamadas (N-Tier)
- Camada de apresentação (UI)
- Camada de negócio (Business Logic)
- Camada de acesso a dados (Data Access)
- Camada de persistência (Database)

#### Cliente-Servidor
- Modelo de comunicação
- Thin client vs. Thick client
- Balanceamento de carga

#### SOA (Service-Oriented Architecture)
- Arquitetura orientada a serviços
- ESB (Enterprise Service Bus)
- Web Services (SOAP)
- Contratos de serviço

#### Microsserviços
- Decomposição em serviços pequenos e independentes
- Comunicação entre serviços
- Service discovery
- Circuit breaker pattern
- Saga pattern para transações distribuídas

### 3.2 APIs e Integrações

#### API RESTful
- Princípios REST (Representational State Transfer)
- Métodos HTTP (GET, POST, PUT, PATCH, DELETE)
- Status codes HTTP
- HATEOAS (Hypermedia as the Engine of Application State)
- Versionamento de APIs
- Idempotência

#### Formatos e Protocolos
- **JSON** (JavaScript Object Notation)
- **JWT** (JSON Web Token) - Autenticação e autorização
- **API Gateway** - Roteamento, segurança, rate limiting

### 3.3 Princípios de Design

#### Arquitetura Limpa (Clean Architecture)
- Separação de responsabilidades
- Independência de frameworks
- Testabilidade
- Camadas: Entidades, Casos de Uso, Interface Adapters, Frameworks

#### Princípios SOLID
- **S** - Single Responsibility Principle (Responsabilidade Única)
- **O** - Open/Closed Principle (Aberto/Fechado)
- **L** - Liskov Substitution Principle (Substituição de Liskov)
- **I** - Interface Segregation Principle (Segregação de Interface)
- **D** - Dependency Inversion Principle (Inversão de Dependência)

#### Outros Princípios
- **DRY** (Don't Repeat Yourself) - Não se repita
- **KISS** (Keep It Simple, Stupid) - Mantenha simples

### 3.4 Padrões de Projeto GoF (Gang of Four)

#### Padrões Criacionais
- **Singleton** - Instância única
- **Factory Method** - Criação de objetos através de interface
- **Abstract Factory** - Família de objetos relacionados
- **Builder** - Construção passo a passo
- **Prototype** - Clonagem de objetos

#### Padrões Estruturais
- **Adapter** - Adaptação de interfaces
- **Bridge** - Separação de abstração e implementação
- **Composite** - Estrutura de árvore
- **Decorator** - Adição de responsabilidades dinamicamente
- **Facade** - Interface simplificada
- **Flyweight** - Compartilhamento de objetos
- **Proxy** - Representante de objeto

#### Padrões Comportamentais
- **Chain of Responsibility** - Cadeia de processamento
- **Command** - Encapsulamento de requisições
- **Iterator** - Acesso sequencial a elementos
- **Mediator** - Comunicação centralizada
- **Memento** - Captura de estado
- **Observer** - Notificação de mudanças
- **State** - Alteração de comportamento por estado
- **Strategy** - Família de algoritmos intercambiáveis
- **Template Method** - Esqueleto de algoritmo
- **Visitor** - Operações sobre estrutura de objetos

### 3.5 Arquiteturas Modernas

#### Event-Driven Architecture
- Eventos e mensagens
- Event sourcing
- CQRS (Command Query Responsibility Segregation)
- Message brokers (RabbitMQ, Kafka)

#### Pipelines de Dados
- ETL (Extract, Transform, Load)
- Streaming de dados
- Processamento em batch

- Adaptável e distinguível
- Acessível por teclado
- Tempo suficiente para leitura
- Prevenção de convulsões
- Navegável e identificável

### 10.2 e-MAG (Modelo de Acessibilidade em Governo Eletrônico)

#### Diretrizes
- Baseado no WCAG
- Adaptado para sites governamentais brasileiros
- Recomendações de boas práticas
- Seções: marcação, comportamento, conteúdo/informação, apresentação/design, multimídia, formulário

### 10.3 Boas Práticas de Design Inclusivo

#### Desenvolvimento Acessível
- HTML semântico (tags apropriadas)
- ARIA (Accessible Rich Internet Applications)
- Contraste de cores adequado
- Tamanho de fonte legível
- Navegação por teclado
- Compatibilidade com leitores de tela
- Formulários acessíveis com labels

#### Testes de Acessibilidade
- Ferramentas automatizadas (axe, WAVE, Lighthouse)
- Testes manuais com leitores de tela
- Validação de HTML e CSS
- Testes com usuários com deficiência
